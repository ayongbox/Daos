# 架构总览

- 状态：已接受
- 关联：ADR-0001、ADR-0002、ADR-0003、`docs/architecture/project-layout.md`

## 分层

```text
┌──────────────────────────────────────────────────────────┐
│ 接入层  REST API / 开放 API / OIDC 登录 / Webhook          │
├──────────────────────────────────────────────────────────┤
│ 应用层  应用编排：建模发布、表单提交、流程流转、数据导入导出   │
├──────────────────────────────────────────────────────────┤
│ 领域层  元数据域 / 权限域 / 数据域 / 流程域 / 扩展域          │
├──────────────────────────────────────────────────────────┤
│ 基础设施  Baseon starters：数据源、租户、缓存、审计、安全     │
├──────────────────────────────────────────────────────────┤
│ 存储层  MySQL 8.0 / PostgreSQL 15 / Redis / 对象存储        │
└──────────────────────────────────────────────────────────┘
        前端：console（设计器与配置） / runtime（渲染与审批）
```

规则：跨层只能自上而下调用；领域层不依赖基础设施层的具体实现，只依赖其契约。

## 模块依赖

```text
daos-web ──→ daos-runtime ──→ daos-core
     │                                    ↑
     └──→ daos-license ───────────────┘
daos-ext-* ──────────────────────────┘（仅 SPI）
```

- 依赖单向下行，禁止反向与循环；
- `core` 是唯一共享契约层，任何跨模块的数据结构都在这里定义；
- `ext-*` 只能通过 `core.spi` 接入，不得依赖 `runtime`。

## 运行时拓扑

```text
Browser
  │
Nginx（静态资源 + 反向代理）
  │
daos-web（单 JVM，模块化单体）
  ├── Flowable 7（同进程，独立 schema flowable）
  ├── daos-runtime
  └── daos-core
  │
  ├── MySQL 8.0 / PostgreSQL 15
  │     ├── cy_*        平台元数据（保留前缀）
  │     ├── 用户定义表   业务数据，禁止使用 cy_ 前缀
  │     └── flowable    ACT_* 流程表
  ├── Redis（缓存、锁、会话）
  └── 对象存储（附件，MinIO 或 S3 兼容）
```

## 四条关键链路

| 链路 | 步骤 | 权限注入点 |
|---|---|---|
| 建模发布 | 设计器产出元数据 → 草稿保存 → 发布校验 → DDL 编译 → 迁移执行 → 版本快照 | 发布前校验当前用户的应用级权限 |
| 数据查询 | 请求 → 权限裁决 → 查询编译 → 数据服务 → 返回 | 编译期注入租户条件、数据范围、行级条件 |
| 表单渲染 | 元数据 + 权限快照 → 渲染树 → 前端 renderer | 编译期写死权限快照，运行期不二次计算 |
| 流程审批 | 表单提交 → Flowable 实例 → 任务 → 表单渲染 → 数据写入 | 任务操作走权限裁决；业务数据写入走数据服务 |

关键约束：

- 渲染树编译必须携带权限快照，同一份元数据在不同权限下产出不同渲染树；
- DDL 与查询 AST 保持纯函数，权限与数据范围只在独立重写阶段注入；
- 所有业务数据读写经过数据服务，禁止绕过直连数据库。

## 扩展与授权

```text
社区包启动（无扩展）→ 正常可用
导入 daos.lic → 服务端验签 → 判定 edition / features
拉取或导入签名扩展包 → SPI 装配 → 启用商业能力
```

- License 只做授权，不参与数据迁移；
- 扩展包必须签名，装配失败自动回退社区版；
- Feature 枚举只用于版本归属与扩展存在性校验，社区代码不按 feature 分叉。

## 非目标

社区版不做：多租户运营能力、集群、跨租户治理、组件市场、移动端设计器、数据大屏、离线许可。数据模型始终带 `tenant_id`，为 Plus 预留。

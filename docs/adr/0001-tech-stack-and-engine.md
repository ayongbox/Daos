# ADR-0001 技术栈与引擎选型

- 状态：已接受
- 日期：2026-11-16
- 决策人：项目负责人
- 关联功能：F03-01、F03-02、F03-05，以及阶段 0 前置决策

## 背景

features.md 规定阶段 0 必须以 ADR 固化 BPMN 引擎、表单设计器、建模器的自研 / 嵌入选型，未决策不得进入阶段 3、4。本 ADR 同时确定前端技术栈，因为三个设计器的实现方式依赖它。

约束条件：

- 后端固定为 Spring Boot 3.2.12 + Baseon 脚手架；
- 社区版 Apache-2.0 开源、单机自托管，不引入重型中间件依赖；
- 数据库方言为 MySQL 8.0 与 PostgreSQL 15；
- 开发者不手写前端代码，以 AI Coding 为主，生态语料密度影响实际产出质量。

## 决策

### 1. BPMN 引擎：嵌入 Flowable 7

| 候选 | 结论 |
|---|---|
| Flowable 7 | **采用**。Apache-2.0，原生支持 Spring Boot 3，嵌入式与独立部署皆可 |
| Camunda 8 | 弃用。依赖 Zeebe + Elasticsearch，单机自托管过重，运营组件非开源 |
| Camunda 7 | 弃用。已进入维护期，官方主线转向 8 |
| Activiti 7 | 弃用。社区活跃度低，嵌入式支持弱 |
| 自研引擎 | 弃用。首发工作量不可控，且不构成差异化 |

配套约束：

- 流程定义、任务、实例一律通过 Flowable API 访问，业务代码禁止直连 `ACT_*` 表；
- Flowable 表自带的 `TENANT_ID_` 复用为租户隔离列，与平台 `tenant_id` 模型保持一致，不另建映射；
- `ACT_*` 表的建表与迁移由 Flowable 管理，平台迁移脚本不得修改这些表；
- 阶段 0 需产出「平台表 / Flowable 表」边界清单，明确禁止跨边界 JOIN。

### 2. 表单设计器与建模器：自研

- 表单设计器、数据建模器、BPMN 画布均为自研，不基于第三方低代码平台二次封装。
- 理由：三者是平台核心资产，二次封装会锁死扩展能力，且难以与权限快照、渲染树契约对齐。
- 能力对标明道云，但只做能力层面对标，不复制其交互细节、字段命名与产品文案。

表单设计器能力分档：

| 档位 | 能力 | 对应功能 |
|---|---|---|
| P0 | 基础字段全集、栅格拖拽、新建/编辑/查看三视图、必填/唯一/正则校验、字段显隐与可编辑联动、字段级权限 | F03-02、F03-03、F01-06 |
| P0 | 明细表（子表单）、他表字段 lookup、公式字段、汇总回写主表 | F03-07 |
| P1 | 公开表单、打印模板、移动端独立布局、条码/签名、级联选择 | 首发后补 |
| P2 | AI 生成表单、复杂嵌套子表单、跨应用关联 | 不进入首发 |

建模器仅需覆盖 F03-01：表、字段、关系、索引的可视化编辑，变更统一走结构演进。

BPMN 画布使用 `bpmn-js`（bpmn.io，框架无关）作为图形层，流程语义由 Flowable 承担，画布不参与运行时。

### 3. 前端技术栈：React 18 + TypeScript

| 层 | 选型 |
|---|---|
| 框架 | React 18 + TypeScript 5 |
| 构建 | Vite |
| 组件库 | Ant Design 5 + ProComponents |
| 表单引擎 | Formily（schema 驱动，设计器与运行时共用） |
| 画布与拖拽 | react-flow + dnd-kit |
| 流程图形 | bpmn-js |
| 状态管理 | Zustand |

选型理由：

1. 三个设计器在 React 生态均有直接可用的专业库：Formily 面向低代码表单设计器设计，react-flow 覆盖 ER 图与节点连线，dnd-kit 覆盖拖拽编排；Vue 侧对应库多为移植或功能子集。
2. Ant Design 5 与 ProComponents 的表格、表单、布局能力可直接覆盖视图与报表场景，减少自研。
3. AI Coding 场景下 React + TypeScript 的语料密度更高，生成结果更稳定，长期维护成本更低。

Vue 3 + Element Plus 作为备选记录：模板驱动对 schema 渲染更直观，国内文档丰富，但设计器侧专业库不足，故不采用。

### 4. UI 风格：对齐飞书

- 视觉与交互向飞书 B 端产品对齐，只借鉴布局、配色与交互语言，不复制商标、图标、字体与截图。
- 实现路径：保持 Ant Design 5 + ProComponents，通过 `ConfigProvider` Design Token 与布局层定制，不切换组件库。
- 评估过 Arco Design（字节系，视觉更接近飞书），因缺少 Formily 现成适配与 ProComponents 级封装，放弃。
- 设计令牌、布局、交互与三个设计器的专项要求见 `docs/design/ui-style-guide.md`，该文件是唯一视觉事实源。

## 后果

- 前端渲染层必须与 UI 框架解耦：运行时只消费渲染树，设计器只产出元数据，不得在渲染树中写入 React 组件名或框架特有属性；
- Formily 仅作为渲染与设计器的实现手段，其 schema 不直接对外暴露，平台元数据 schema 仍是唯一契约；
- 引入 Flowable 后，阶段 2 的迁移脚本需与 Flowable 自动建表流程隔离，避免版本冲突；
- 本 ADR 变更需重新过阶段 0 契约评审，不得在实现阶段临时替换引擎或前端框架。

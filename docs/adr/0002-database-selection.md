# ADR-0002 数据库与数据存储选型

- 状态：已接受
- 日期：2026-11-16
- 关联功能：F00-01、F00-02、F01-01、F02-01、F02-03、F05-05
- 前置：ADR-0001

## 背景

平台涉及三类数据，存储特征不同，必须分开定义，否则阶段 0 的 DDL 编译器和迁移脚本无法落地：

1. 平台元数据：应用、表、字段、表单、视图、菜单、流程、权限；
2. 业务数据：用户通过建模器生成的表与数据；
3. 流程运行时：Flowable 的 `ACT_*` 表。

## 决策

### 1. 平台库

- 默认 **MySQL 8.0**，**PostgreSQL 15** 对等支持，不存在「先只支持一种、后补另一种」；
- 社区版允许与业务库同实例部署，通过表前缀隔离：平台表统一 `cy_` 前缀，用户业务表不得使用该前缀；
- 所有平台表包含 `tenant_id`，联合索引以 `tenant_id` 前导；
- 元数据存储采用**核心字段列化 + 扩展字段 JSON 列**（MySQL `JSON` / PostgreSQL `jsonb`）：可按应用、表、版本检索，新增扩展属性不动表结构。

### 2. 业务库

- 通过 `baseon-starter-datasource` 动态数据源接入，支持一个租户对应多个数据源；
- 目标方言为 MySQL 8.0 与 PostgreSQL 15，DDL 一律由编译器按方言输出，禁止手写方言 SQL；
- 业务表结构由建模器元数据推导，必须包含 `tenant_id`，字段与索引上限见验收基线。

### 3. 流程库

- Flowable 使用独立 schema（默认 `flowable`），不与平台表、业务表混放；
- `ACT_*` 表由 Flowable 自动建表与升级，平台迁移脚本禁止修改这些表；
- 阶段 0 产出「平台表 / `ACT_*` 表」边界清单，禁止跨边界 JOIN。

### 4. 迁移与版本

- 平台迁移脚本按方言分目录管理（`mysql/`、`postgresql/`），内容等价；
- 迁移幂等、可重入、兼容 N-1；升级前自动备份；
- 迁移工具在阶段 0 骨架阶段验证后确定，首选 Flyway，不满足双方言幂等要求时改用自研迁移执行器。

## 后果

- 任何涉及 DDL 的变更都要提交两套方言脚本，并在 CI 中同时验证，成本翻倍但不可省略；
- 阶段 2 出口前必须跑通「同一元数据在 MySQL 8.0 与 PostgreSQL 15 编译结果等价」；
- 开发环境默认 MySQL 8.0（Docker Compose 提供），PostgreSQL 验证在 CI 与阶段出口执行；
- `cy_` 前缀为平台保留，建模器需在创建表时校验并拒绝对该前缀的使用。

# 道生平台 · 功能清单与实施顺序

## 定位

本文定义道生低代码平台社区版的首发范围、开源边界、授权与升级方式、实施顺序，作为立项、排期和验收的共同基线。

约定：

| 项 | 值 |
|---|---|
| 平台名 | 道生 / Daos |
| 引擎名 | Baseon |
| 平台包名 | `io.github.ayongbox.daos.*` |
| 引擎包名 | `io.github.ayongbox.*` |
| 配置前缀 | `daos.*` |
| 许可证文件 | `daos.lic` |
| 商业扩展包 | `daos-ext-*.zip`（签名） |
| UI 风格 | 飞书式 B 端视觉，规范见 `docs/design/ui-style-guide.md` |
| 技术选型 | 见 `docs/adr/0001-tech-stack-and-engine.md` |

## 工程分层

```text
daos-platform（parent）
├── daos-core         元数据、编译管线、权限裁决契约
├── daos-runtime      数据服务、查询编译、流程引擎
├── daos-designer     建模器、表单设计器、BPMN 设计器
├── daos-web          控制台后端与前端聚合
├── daos-license      授权与版本能力
└── daos-ext-*        商业扩展包，闭源，通过 SPI 装配
```

约束：

- 业务代码只依赖 `baseon-starter-*`，不单独声明 `baseon-core`，core 由 starter 传递；
- 社区构件开源，商业实现放 `daos-ext-*`，不得打进社区包；
- 构件名不出现 `plus`、`free`、`lite`，版本由 License 决定；
- 配置前缀用 `daos.*`，不要用 `platform.*` 过渡，也不要在代码里覆盖 `baseon.*`。

优先级定义：

- **P0**：首发闭环必需，缺失则无法上线真实业务系统。
- **P1**：首发应有但不作为发布门槛，允许在首发后一个小版本内补齐。
- **P2**：后续增强，不进入首发。

## 版本边界

| 维度 | 社区版（免费） | Plus | 企业版 |
|---|---|---|---|
| 功能闭环 | 建模、表单、视图、权限、流程、数据服务全通 | 不阉割 | 不阉割 |
| 规模 | 1 租户、单实例 | 多租户（≤5）、集群 | 无限租户、跨租户治理 |
| 身份 | 本地账号 + 单个 OIDC | LDAP/AD/钉钉/企微/SCIM | 多源聚合、强制 SSO |
| 合规 | 7 天操作与字段级变更日志 | 180 天、检索导出 | 不可篡改、等保、SIEM |
| 交付 | Docker 单机自托管 | 标准私有化 | 信创、离线升级、HA、SLA |
| 生态 | 本地组件包、3 个连接器 | 私有组件仓库、全量连接器 | 组件市场、集成平台 |
| 授权 | 无强制 License，Apache-2.0 | 签名 License + 商业扩展包 | 离线 License + 离线扩展包 |
| 升级 | 原地升级平台与社区扩展 | 导入 License 原地升级 | 离线升级编排、版本兼容矩阵 |

计费锚点：按**租户数、环境数、节点数、支持等级**计量，不按最终用户数计量。

注意：首发社区版已含完整功能闭环，Plus 的差异集中在多租户、集群、身份源与合规。对中腰部客户付费动机偏弱，需保留移动端设计器、高级报表等高频刚需作为 Plus 抓手。

## 开源边界与授权分层

原则：**社区版不靠 License 阉割，商业版不靠开关防护。**

| 层 | 做法 | 作用 |
|---|---|---|
| 合法性 | 付费版签名 License、公钥验签、到期降级 | 防伪造、防误用、管到期 |
| 代码边界 | 商业能力放闭源扩展包，通过 `daos.spi.*` 装配 | 绕过开关也拿不到实现 |
| 服务端 | 多租户控制面、组件市场、授权服务独立部署 | 本地无法绕过 |
| 法律与商业 | EULA、商标、审计条款、SLA、支持 | 约束企业规模白嫖 |

明确接受：本地校验可以被删除，不承诺防破解。开源仓库只包含社区版完整闭环；商业扩展包不进社区发行包，升级时按需拉取或离线导入。

- 社区版：Apache-2.0，无强制 License，不限用户与应用。
- 商业版：闭源扩展包 + 签名 License；License 只做授权，不参与数据迁移。

## 首发明确不做

多租户运营能力（数据模型始终带 `tenant_id`）、集群、信创适配、组件市场、移动端设计器、AI 生成、数据大屏、跨环境迁移、离线许可、等保 2.0 合规（社区版审计仅留存 7 天，不满足六个月要求）。

以上为硬边界，超出范围的请求一律进入 Plus / 企业版需求池。

## 实施顺序

### 总览

| 阶段 | 里程碑 | 覆盖功能 | 出口标准 |
|---|---|---|---|
| 0 | M0 契约冻结 | F00-01 ~ F00-06 | schema v1 与 SPI 契约冻结，三路编译快照通过，越权矩阵可运行 |
| 1 | M1 可登录可授权 | F01-01 ~ F01-07、F01-09 | 单租户登录、角色分配、租户隔离与行/字段级权限和数据范围生效、审计可查 |
| 2 | M2 可建表可录数 | F02-01 ~ F02-03、F02-06 | 建模 → DDL → CRUD → 查询 → 迁移回滚，附件上传下载全通 |
| 3 | M3 可搭应用 | F03-01 ~ F03-04、F03-07 | 表单、视图、菜单可配置并发布，明细表与关联选择可用，服务端重校验生效 |
| 4 | M4 可跑流程 | F03-05、F03-06、F03-08 | 请假类流程端到端跑通，会签/撤回/转办可用，表单与业务数据映射正确 |
| 5 | M5 可交付 | F05-01 ~ F05-04、F05-07、F01-08 | Docker 单机部署、导出备份可用、安全基线生效、社区版无授权限制 |
| 6 | M6 可升级 | F05-05、F05-06 | 社区版导入 License 原地升级，失败可回滚，无数据迁移 |
| 7 | M7 可扩展 | F04-01 ~ F04-03、F02-04、F02-05、F02-07 | 脚本钩子、组件包、Webhook、调度与开放 API 可用 |
| 8 | M8 发布候选 | P0 全量 32 项 | P0 验收清单全绿，回归与性能基线达标；P1 8 项不阻塞首发 |

### 阶段 0：契约与骨架

- 交付：八类元数据 schema、三路编译管线、字典与权限点定义、扩展装配 SPI、验证套件骨架、可观测性埋点规范、部署骨架。
- 关键动作：先冻结 `schema v1` 与 SPI 契约，再允许并行；同时冻结三项底座约定：租户隔离采用 `tenant_id` 列模型（全部业务表统一带 `tenant_id`，联合索引以 `tenant_id` 前导）、渲染树编译入参含权限快照、会话/文件/调度锁/缓存全部走抽象接口且禁止业务代码直连本地状态。任何 schema 变更走版本升级，不允许直接改字段。
- 前置决策：BPMN 引擎、表单设计器、建模器的自研 / 嵌入选型以 ADR 固化，未决策不得进入阶段 3、4。
- 出口：同一份元数据分别编译出的 DDL、查询 AST、渲染树可快照比对（渲染树固定权限快照）；DDL 在 MySQL 8.0 与 PostgreSQL 15 方言下均通过；越权矩阵用例可自动运行；无商业扩展时社区版可正常启动。
- 风险：元数据模型返工会拖垮全盘，此阶段不追求功能完整，只追求契约稳定。

### 阶段 1：身份与权限

- 交付：租户上下文、组织树、本地账号与 OIDC、平台/应用两级角色、权限裁决、数据范围、审计。
- 关键动作：权限裁决先冻结 API，再实现。数据服务的租户隔离、行级权限与数据范围注入只依赖该 API。
- 出口：同一查询在不同角色、不同数据范围下返回不同行/字段；前端篡改参数无法越权；审计能定位到字段级变更。

### 阶段 2：数据内核

- 交付：数据服务、查询编译、结构演进、附件与文件存储。
- 关键动作：所有读写必须经过数据服务，禁止业务代码直连数据库；查询编译是行级权限与数据范围的唯一注入点；文件读写必须经过存储抽象。
- 出口：建模器改字段可生成迁移计划并执行、可回滚；并发更新有乐观锁保护；导入导出可跑通；附件可上传并按权限下载。
- 并行说明：本阶段可与阶段 1 并行，前置条件是阶段 0 冻结的权限裁决接口。

### 阶段 3：建模与界面

- 交付：数据建模器、表单设计器、表单运行时、视图与报表、表单高级字段。
- 关键动作：设计器只产出元数据，不直接产出代码；运行时完全由渲染树驱动。
- 出口：不写代码可完成“建表 → 配表单 → 配列表 → 发布菜单”并录入数据；明细表与关联选择可正常读写。
- 并行说明：设计器前端可在阶段 0 后启动，运行时联调依赖阶段 2。

### 阶段 4：流程

- 交付：BPMN 设计器、BPMN 引擎、流程人机交互。
- 关键动作：流程变量与业务数据的映射规则先定，再实现引擎；表单绑定复用阶段 3 的渲染树。
- 出口：发起 → 审批（含会签/或签）→ 网关分支 → 结束全链路跑通；撤回、转办、加签、催办可用；流程中的业务数据变更仍受权限裁决约束。

### 阶段 5：交付

- 交付：可观测性、商业授权、部署与初始化、导出与备份、安全基线、配置中心。
- 关键动作：社区版不强制 License；付费版校验只在服务端；到期进入 30 天宽限期，随后商业功能只读，数据始终可导出。
- 出口：一台干净机器用 Docker Compose 完成社区版部署、初始化并跑通示例应用；安全基线生效（登录锁定、限流、敏感字段加密）；导入测试 License 后商业功能可启用。

### 阶段 6：升级与商业交付

- 交付：升级与回滚、商业扩展包交付，以及 SPI 装配的联调。
- 关键动作：平台内核与商业扩展分轨升级；扩展包必须签名；迁移脚本幂等且兼容 N-1；升级前自动备份，失败可回滚；v1.0.0 冻结为 N-1 基线，其镜像与迁移脚本长期保留，作为升级与回滚的最低兼容目标。
- 出口：社区版环境导入 License → 在线拉取商业扩展包 → Plus 功能生效 → 回滚社区版，全过程无数据迁移、无业务中断；离线包导入作为 P1 在首个补丁版本补齐。

### 阶段 7：扩展

- 交付：脚本沙箱、组件注册、集成与通知、事件总线、调度器、开放 API 与凭证。
- 关键动作：沙箱四道限制必须默认开启；组件包必须校验签名与依赖白名单；开放 API 凭证与配额走独立鉴权链，不复用会话。
- 出口：脚本超时/超内存可被拦截；第三方 Webhook 失败可重试并进入死信；开放 API 可限流并按凭证审计。

### 阶段 8：发布候选

- 交付：P0 全量验收、回归、性能基线、文档。
- 出口：P0 32 项逐项验收通过；越权矩阵零漏判；《验收基线》指标全部达标；P1 8 项随首个功能版本补齐，不阻塞首发。

## 升级机制

三条轨道解耦：

| 轨道 | 载体 | 操作 | 回滚 |
|---|---|---|---|
| 平台内核 | `daos-core` 发行包 / 容器镜像 | 在线或离线升级 | 镜像与迁移脚本版本回退 |
| 商业扩展 | 签名扩展包（在线仓库或离线包） | License 激活后拉取或导入 | 卸载扩展包，保留数据 |
| 授权 | `daos.lic` | 后台上传导入 | 换回旧 License |

社区版 → Plus / 企业版：

```text
社区版运行
  → 后台上传 daos.lic
  → 验签 + 校验 installationId / limits / features
  → 在线拉取或离线导入商业扩展包
  → 执行幂等迁移（只初始化数据，不改社区表结构；多租户按租户记录开通）
  → 启用 Feature
  → 健康检查
  → 显示 Plus / 企业版
```

升级规则：

1. 平台与扩展分两步升级，不要求同版本号，但必须在兼容矩阵内。
2. 商业表位于平台级 schema，社区版安装时预建空表；社区业务表自 1.0 起已含 `tenant_id`，启用多租户只做租户数据初始化与可见性切换，不新增列，避免运行期 DDL。
3. 迁移脚本幂等、可重入、兼容 N-1；v1.0.0 作为 N-1 基线长期保留；升级前自动备份。
4. 在线与离线使用同一批签名制品。
5. License 到期：30 天宽限 → 商业功能只读 → 社区功能继续可用 → 数据可导出。
6. 社区版升级过程不要求停机；商业扩展包加载失败时自动回退社区版。

## 验收基线（v1）

以下指标作为阶段 8 与 DoD 的量化门槛，未达标的功能项不得标记完成：

| 维度 | 基线 |
|---|---|
| 数据库 | MySQL 8.0、PostgreSQL 15；同一元数据在两库编译结果等价 |
| 单表规模 | ≤500 万行；超出由 Plus 的分区 / 归档承接 |
| 元数据规模 | 单应用 ≤200 张表、单租户 ≤500 张表、单表 ≤100 字段、≤10 个索引、单租户 ≤50 个应用 |
| 并发 | 200 在线用户、50 并发写；基准机型 4C8G 单机 |
| 列表查询 | P95 ≤500ms（100 万行、20 列、含行级权限与数据范围）；慢查询阈值 1s |
| 表单提交 | P95 ≤300ms，含权限裁决与审计写入 |
| 元数据发布 | 含 DDL 的发布 ≤30s，失败自动回滚 |
| 导入导出 | 导入 ≥1 万行/分钟；导出 10 万行 ≤60s；异步执行，失败可续 |
| 附件 | 单文件 ≤100MB、单记录 ≤20 个附件；存储后端可替换 |
| 三路编译 | 50 表规模下 ≤5s，作为 CI 回归门槛 |
| 备份恢复 | RPO ≤24h、RTO ≤2h；每日全量 + 恢复演练 |
| 审计查询 | 7 天数据按人/应用查询 ≤2s |
| 脚本沙箱 | 墙钟超时 5s、CPU 2s、内存 128MB、禁网络；四道限制默认开启 |
| 安全 | 登录失败 5 次锁定 15 分钟；匿名接口默认限流 10 QPS |
| 浏览器 | Chrome、Edge 最近两个大版本；不支持 IE |

## 完成定义（DoD）

每个功能项完成需同时满足：

1. 单元测试覆盖核心分支，集成测试覆盖主链路。
2. 验证套件新增对应用例，越权场景必须有反例。
3. 配置项归入 `daos.*`；社区版功能不得依赖 License，付费功能必须在 Feature 枚举登记归属，实现放闭源扩展包，社区代码不得按 feature 分叉。
4. 模块文档更新到 `docs/`，包含配置项与失败场景。
5. 不引入绕过数据服务或权限裁决的直连路径。
6. 性能、容量与安全指标达到《验收基线》；超出基线的场景必须写明降级行为。

## 关键约束

1. 版本号与版本层级都不进入构件名；`plus` / `free` / `lite` 禁止出现在坐标中。
2. 同一发行版本内，社区构件开源、商业构件闭源，通过 SPI 装配，商业实现不得打进社区包。
3. 配置前缀直接用 `daos.*`，不做 `platform.*` 过渡。
4. Baseon 只作为底座单向被依赖，平台不反向修改引擎包名与坐标。
5. 社区版不做多租户运营能力，但租户上下文必须预留；隔离模型固定为 `tenant_id` 列，全部业务表自 1.0 起包含 `tenant_id` 且联合索引以其前导，Plus 启用多租户不改社区表结构。
6. 社区版不强制 License；付费能力由闭源扩展包 + 签名 License 提供。
7. 升级必须幂等、可回滚、兼容 N-1；平台与扩展版本解耦，维护兼容矩阵。
8. 渲染树编译必须固定权限快照；DDL 与查询 AST 为纯函数，行级权限与数据范围只在独立重写阶段注入。
9. 会话、文件、调度锁、缓存一律通过抽象接口访问，禁止业务代码直接依赖本地状态，保证 Plus 可替换为共享实现。
10. 数据库方言矩阵为 MySQL 8.0 与 PostgreSQL 15；DDL 与查询必须编译输出，禁止拼接裸 SQL。
11. Feature 枚举只做版本归属声明与扩展存在性校验，社区代码不得按 feature 分叉业务实现。
12. BPMN 引擎、表单设计器、建模器的自研 / 嵌入选型在阶段 0 以 ADR 固化，变更需重新过契约评审。
